# §23 衣物平铺展示图（2026-10-25）

用户确认将裁剪后的衣物去模特、背景和购物文字，生成单独衣服平铺图，并优先使用现有 WorkBuddy 积分。识别、属性和搭配继续 DS4.1 Flash；生成图片使用官方 ImageGen 图生图工具及 hunyuan-image-alpha-edit，不能把 DS 的文字输出当作图片。

## 已有证据

官方 npm 个人 CLI 2.173.0 正常登录来源 copilot.tencent.com，DS4.1 返回 OK。指定 NoDefer(ImageGen) 后，手机现有米白外套样图实际生成成功，人物已去除；本次工具返回 credit=5.71，耗时20.705秒。这个数字不是固定单张报价。原 native CLI 被 Windows 应用控制拦截；采用官方文档支持的 npm 发行版，不修改系统策略、不提取凭证。桌面自带精简 CLI 不能代表独立个人 CLI 的登录状态。

## 数据与交互契约

- 三种图片分开：完整原截图、真实裁剪图、AI生成展示图。image_path/image_hash继续指向真实裁剪图，识别和去重依据保持；原截图及展示图用显式独立字段保存，不塞进tags或thumbnail_path。schema以增量迁移补字段，旧衣物原样可用。
- 录入入口及默认采用按§23.2统一流程执行；详情仍保留独立生成与明确采用操作。照片轻点仍裁剪真实来源。
- 提示生成细节可能与实物不同；不宣称还原被遮挡部分。生成图不触发属性识别或重填。表单、更多属性和保存按钮继续正常流，生成状态只更新照片区域，保留输入法、焦点和手填所有权。
- 生成任务以随机requestId、真实源图hash和来源revision绑定，电脑侧持久化状态与结果；重复提交同requestId不再次出图。状态查询不扣一次新的生图费。超时/刷新先查询已有任务，不自动重发；电脑重启后无法确认的任务显示中断，用户决定是否重做。
- 生成过程中可收起面板继续；同件重复生成、重裁、保存、跳过暂时锁定，字段可继续填写。任务完成/失败解除操作锁。新来源使旧结果失效，取消裁剪不改变状态。
- 入库原图、裁剪图及已采用展示图同次事务确认；保存pending冻结相同来源及展示字节，重试不重新生成。重复衣物仍按真实裁剪字节判断，不按随机生成图片判断。
- 电脑中转复用已有配对和个人登录，主模型固定DS4.1。图像任务只允许ImageGen，固定输入/输出目录、单次调用、无其他工具/MCP；工具前置校验阻止更改路径或多次生成。客户端不提供任意提示词、URL或命令。
- 电脑输入图在生成结束后删除。生成结果缓存期限24小时，在后续查询/任务请求时清理过期文件；离线闲置期间不运行定时清理。保留不含图片的小任务指纹，防止过期同ID重发扣费。手机已保存的原图/裁剪图/生成图由用户衣物生命周期管理。失败不覆盖既有展示图。删除衣物清理明确归属的图片。

## 验收

两位只读审查分别负责数据/桥接与前端状态；主agent唯一写入。验证任务幂等、来源变化、旧响应、刷新查询、生成失败与恢复、存储失败、模型来源和路径限制、源图与展示图原子入库及回滚、切回源图、换图失效和删除清理；再做三视口、pytest、83项smoke、对比度、APK解包及手机数据指纹保护。测试默认合成模型/临时目录，真实积分调用有明确记录，不自动重复。

## §23.1 本机展示整理（2026-10-26）

用户要求把去除角落水印的处理写进逻辑。采用本机展示副本：录入、详情、衣橱和搭配统一使用 `flatlay-display.js`，不改原截图、真实裁剪图、完整生成文件或识别/去重依据，不调用生成或识别模型，不新增积分消耗。未来新结果和现有已采用结果均走同一规则。

- 不裁整条底边、不缩放或移动衣物。实际样本的裤脚/袖口已靠近下边缘，统一裁底边会损失衣物。只在右下角候选范围检测已验证平台双行亮色角标，识别小型连通组件并与64×32文字形状位图核对；位图只含角标形状，不含用户衣物或账号资料。
- 按原始分辨率检查角标框及其保护区，深色细节、透明像素、连通浅色主体、未知文字/普通亮点、背景不确定时保留完整图。只在可确认的局部留白框延续邻近背景，框外RGBA保持一致。它不是通用抠图/语义分割；平台更换角标或不同背景时应保守回退。
- 详情/录入新增“完整平铺图”切换，不触发采用或再次生成。整理失败的可见提示说明保留完整图，用户仍可核对后使用；原图选项不做角落处理。异步回调检查当前节点、来源及模式，不能把旧处理结果覆盖到新图或完整图。
- 双任务队列，32份Blob结果缓存。卡片靠近可视区再处理，离开DOM且尚未开始的任务取消；节点替换/移除撤销其专属对象URL。临时解码失败不长期缓存。新模块加入SW v30预缓存/critical两份清单。
- 对现有20图实测：15张整理，4张无可见角标保持原样，米白外套（17）因袖口阴影接近角标而保留完整图。15张处理图的检测框外RGBA逐像素一致。完整生成文件始终可查看，不能把“自动整理”宣称为所有图片均能安全去除标记。

## §23.2 录入一键识别并生成（2026-10-26）

用户确认交互预览：录入取消两个并列功能，显式点击“识别”后先识别真实衣物属性，随后生成平铺图；结果默认选作卡片，仍由用户确认保存入库。后台DS4.1识别和ImageGen生图的两部分调用保持，不能把生成图当作识别证据。

- `photo-import.js`负责单件串行编排，`import-assistant.js`负责统一入口/状态/比较；共享`flatlay.js`保留稳定任务ID和同源校验，详情行为不变。更新样式、SW双清单和离线版本；不改schema、API、模型配置及真实数据。
- 选图、保存下一件、重新裁剪、追加照片、恢复草稿均不自动发起识别或生图。识别过程结合真实裁剪图与原图描述；识别拿不准留空。品类不确定时等待用户选择，同一录入意图再继续生图。用户手动编辑过的字段（包括主动留空）不被识别覆盖。
- 识别成功即填入属性，然后生成展示图和本机角落整理。过程状态只更新照片/统一操作区，保留属性DOM、输入法、手填值和选区。生成中可编辑属性和收起面板；保存、跳过与重裁按当前任务锁定。品类变化时解除旧图默认采用，提示核对。
- 生图成功默认采用；裁剪图/整理图/完整生成图只切预览，明确“改用裁剪图”才改选择。原截图与真实裁剪来源仍单独保存，确认保存后才入库。已有同源平铺图时重新识别只更新属性并复用图片；更多属性内提供明确另计积分的重生成。
- 识别失败不接着生图，保留输入；生图失败仅重试图像步骤或先用裁剪图保存。超时/刷新查询稳定原任务，不自动重发；识别阶段刷新显示中断，不隐式重启收费流程。明确重生成才创建新任务。照片来源变化清掉旧任务授权与展示，取消裁剪保留原来源。
- 验证使用系统临时库、非默认端口、假识别与假生图服务：双击、识别→生图、两阶段失败、类别留空与手选、手填/IME、来源变化、同源复用、刷新/收起/断点、未知任务查询、存储失败、逐件保存和旧草稿；三视口及真机检查、APK解包一致性、更新前后手机衣物/照片/草稿指纹。两位只读审查分查流程与UI/资源，主agent唯一写入。

## §23.3 白底展示与已有平铺图整理（2026-10-27）

用户要求衣橱和添置页的衣物卡片统一白底，并将要求加入现有一键识别流程；同时授权用新WorkBuddy账号积分处理旧灰底图。模型保持不变：文字/识别为DS4.1，图像编辑为hunyuan-image-alpha-edit。

- 衣橱、添置初始拼图/缩略图/搭配图、衣物详情及飞行照片、搭配图片、录入照片容器统一使用surface白色。页面底色、玻璃层和轮廓示意的装饰背景保持原有层级。SW v36，不新增前端模块。
- 一键识别仍先分析真实来源，再由既有图像步骤生成平铺图。中央make_prompt明确电商纯白#FFFFFF、均匀留白、不生成灰蓝背景/渐变/场景或投影，并保留衣物原色、纹理、标志和已有平铺形态。Hunyuan请求固定revise=false，关闭供应商的提示自动改写；工具守卫同时核对该值，遗漏或改变即拒绝。没有换模型、自动补调用或新增按钮。
- CSS无法改变图片已有底色。旧图先备份，以已有平铺图作图生图参考，结果检查四周68个3×3采样并逐件视觉核对；边缘检查只是必要条件，不能取代完整背景和衣物细节核查。已白的旧图也需视觉核对后保留。仅查看/采用不会重新识别或生成，源截图和衣物属性保持。
- 本次批处理每件持久化稳定job ID后提交；超时/unknown只查询原ID。白底不合格即停止后续提交，显式修正使用新ID并保留旧结果与用量记录。不得把未采用或仍未知的结果计作成功。
- POST /items/{item_id}/presentation新增可选expected_display_path；同一写事务内核对来源hash和预期旧展示路径，冲突409保留用户期间更换的图片。旧调用不传参数时兼容原行为。批处理采用前确认手机支持该字段，视觉approved且边缘检查通过后才写入；响应丢失先核对结果哈希，避免重复采用。
- 不用浅色阈值整幅涂白；此法会误改近背景色的浅衣物/印花，试验已撤下，不进入应用产物。纯白生成要求仍须实际结果验证，不能把提示文字当作保证。

## §23.4 多选后自动准备（2026-10-28）

用户确认auto-import-preview。本节替代§23.2中“选图不自动处理”的规则：本次新选择/追加的照片，图片及授权进度持久化成功后自动逐件识别属性、生成白底平铺图。识别仍基于真实来源和必要的原图描述，不拿生成图重新识别；未知品类留空并等待本件确认，继续准备其余图片。后台不改变用户当前查看位置，不自动入库；保存/跳过仍逐件操作，无集中检查页，不新增积分说明字段。

队列以batch/item/revision/attempt和稳定生图ID绑定，一次准备一件，人工重试也排入同一队列。后台只回填AI拥有的空字段，不覆盖手填、主动清空或IME组字字段；当前表单/更多属性DOM保持。切换缩略图先锁定保存/跳过并持久化旧件，表单读写核对item ID。品类在生图ID落盘期间变化不得按旧品类POST，已发出的旧结果仍可保留核对。

收起面板继续处理；刷新/重入不恢复收费授权，已有starting/running/waiting平铺任务先查询同一ID，识别中断不自动重发。旧草稿的未开始项目须点击“继续自动准备”；已有失败项目留给单件显式重试，不混入整批重跑。选择品类仅在本会话授权且未暂停时自动续链，旧草稿或已暂停时等待明确继续。

网络/超时/鉴权/额度与不确定生图结果暂停整批；恢复时先查询未知原任务，再处理未开始项。不按供应商中文字符串猜错误类别；无机器分类的生图失败保守暂停。出队及新请求前重新核对暂停代次、授权、来源、实际持久化结果；离开/暂停/改源/保存失败期间不新发请求。单件输出结构不合格可停留该件继续其余，未知服务故障不自动重试。模型及原图保留规则不变。
