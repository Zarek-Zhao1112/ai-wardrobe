# UI 设计契约

> **冻结日期**：2026-10-15。这是一份**规格**：前端"应该长什么样、为什么这么定"。
> 改动它要先改这份文件、再改代码 —— 不是反过来。
> 工具定义在 `web/css/tokens.css`；这里只写**决定与理由**。

## 0. 视觉基准

Apple（取自 `awesome-design-md/design-md/apple/DESIGN.md`）。它自己的原话最能说明：

- **"UI chrome recedes so the product can speak"** —— 界面让位给内容（我们的内容是衣服照片）
- **"no decorative gradients, no shadows on chrome"** —— 不加装饰渐变、界面不加阴影
- 唯一强调色 + 负字距 + 大留白

## 1. Design Token

| 类别 | 决定 | 为什么 |
|---|---|---|
| 强调色 | `#0066cc` **苹果蓝** | 用户拍板（原 `#2f6f4f` 绿） |
| 中性色 | `#f5f5f7` / `#1d1d1f` / `#e0e0e0` | 对齐 Apple 灰阶 |
| 字阶 | **32 / 24 / 20 / 17 / 15 / 13 / 12** | 原来只有 14px 一个基准，层次分不开 |
| 字距 | 大标题 `-0.02em`、小标题 `-0.01em` | Apple 的签名细节 |
| 间距 | **4 / 8 / 12 / 16 / 24 / 32** | 8 的倍数，改稿时心算不费劲 |
| 圆角 | **8 / 12 / 16** 三档 | 原来只有 10px 一档 |
| 阴影 | 极轻，只给真正"浮起"的元素（卡片/弹层） | Apple 原话 |

## 2. 断点

| 名称 | 宽度 | 布局 |
|---|---|---|
| **手机** | < 640px | **单列 + 底部 tab 栏** |
| 平板 / 桌面 | ≥ 640px | 顶栏导航 + **卡片网格 `auto-fill` 自适应**；内容 `max-width: 1100px` 居中 |

> ★ **v1 写的是「平板 640–1024 → 双列」，验收时推翻了。**
> 依据：两个独立来源都量到 768px 下 `.grid` 是 4 列、1024px 是 5 列，而不是 2 列。
> 而且"自适应"本来就比固定列数好 —— 照片格子的最佳列数取决于宽度，
> 写死 2 列会让平板留一大片空白。
> 修正：**不规定平板/桌面的固定列数**，由 `.grid` 的 `minmax(168px, 1fr)` 决定
> （实测 390→2 列、768→4 列、1440→6 列）。手机仍是单列的那部分见 §4。

## 4. 手机端约定（重点）

- **底部 tab 栏**（56px）：衣橱 / 录入 / 缺口 / 搭配（=`app.js` 里 `VIEWS` 的实际顺序）
- **所有可点元素 ≥ 44×44px**（Apple HIG 的触控目标底线）
- **安全区**：底部留 `env(safe-area-inset-bottom)`（全面屏手势条）
- **页面要留出底部栏的高度**（`body { padding-bottom }`），否则滚到底时最后一段内容
  会落在固定栏底下 —— 这条**必须写在 `style.css`**，放 token 层会被 `html, body{padding:0}` 覆盖掉（踩过）
- **表单 / 详情页单列**；卡片网格是**照片格**，手机上 2 列（不是 1 列）
- 避免横向滚动；宽表用 `.tbl-wrap` 包一层
- 表单在手机上：`input` 字号 ≥ 16px（否则 iOS 会自动放大）

## 5. PWA（「装到手机上」的形态）

服务已经跑在手机里（`127.0.0.1:8787`），PWA 只差：

- [x] `manifest.webmanifest`（名称、图标、`display: standalone`、主题色）
- [x] Service Worker（离线缓存静态资源；数据靠本地服务）
- [x] 图标 192×192 / 512×512（另加 `maskable` 512 与 `apple-touch` 180）
- [ ] 手机浏览器「添加到主屏幕」后是独立图标 + 全屏 ← **待真机验证**

**缓存策略**（`web/sw.js`，刻意简单）：

| 资源 | 策略 | 为什么 |
|---|---|---|
| 外壳（HTML/CSS/JS/manifest） | **网络优先**，失败回落缓存 | 自托管要随时更新；服务在本机，网络优先几乎零代价 |
| 图片（`images` 目录） | **网络优先**，缓存只当离线兜底 | ★ **原写"缓存优先"，前提就错了**（见下） |
| API（items / outfits / health…） | **完全不拦截** | 缓存 API 会让用户看到过期衣橱 —— 最坏的一类 bug |

> ★★ **图片缓存：v1 的「缓存优先」被推翻了。**
> v1 的理由是「图片是不可变内容（文件名唯一）」—— **这个前提是假的**：
> 文件名其实是 `<单品id>.<扩展名>`（`services/images.py` 注释明说"重新上传就是覆盖"）。
> 于是换一张**同扩展名**的照片时 URL 完全不变 → 缓存永久命中旧图，
> 界面一直显示旧照片，而接口返回 200、一切"看起来成功"。**这是静默错误**：
> 用户会照着错的照片判断穿什么。
> 修正：图片改**网络优先**（服务就在本机，没有延迟代价），并把 `VERSION` 从 v1 提到 v2
> 以清掉旧缓存桶。
>
> 一般化：**选缓存策略前先确认「URL 是否真的随内容变」** —— 别拿"名字看起来唯一"当依据。

> ⚠️ **只有安全上下文能注册 SW**：`https`、`localhost`、`127.0.0.1`。
> 所以手机上用 `http://127.0.0.1:8787` 打开能装成 App，用局域网 IP
> （`http://192.168.x.x:8787`）打开**装不了** —— 浏览器规矩，不是我们的 bug。

### ★ 后端没起来时，页面得"说人话"

自托管特有的一个场景：**首页是后端自己发出来的** —— 后端没在跑时，浏览器连 HTML
都拿不到，只会显示它自己那张"无法访问此网站"的白页。用户看到那个只会觉得**坏了**，
而其实只是"后端还没启动"。

处置：SW 用**缓存里的外壳**兜底把页面渲染出来（网络优先 + 缓存回落，见上表）；
页面发现 `/health` 不通，就整页换成一张**照着做就行**的引导页
（`app.js: renderBackendDown`）—— 说清"打开 Termux 就行"，外加一个「重试」按钮。

> 这条只有在**「按需启动」**这种部署方式下才显得必要：不常驻之后，
> "打开 App 时后端还没起"是**常态**，不是异常。

## 6. Definition of Done

- [x] 桌面 **1440×900** 与手机 **390×844** 都**无横向滚动**（含 `#gaps` / `#add` / `#outfits`）
- [x] 手机上所有可点元素 **≥ 44px**（CDP 断言：#gaps 6 个 / #add 108 个 / #outfits 9 个控件全部达标）
- [x] **滚到底时内容不被底部 tab 栏遮住**（`hidden_px` 全为 0；这条断言**自证过**：打掉占位后会报 32px 遮挡）
- [x] 颜色 / 字号 / 间距**全部来自 token**，无硬编码（例外清单见下表）
- [x] **文字对比度达 WCAG AA**（`scripts/check_contrast.py`，15 组全 ≥4.5:1）
- [x] 无 console 报错（含 warning）
- [x] **后端没起来时显示引导页**，而不是浏览器的错误白页
      （端到端验过：停后端 → 重载 → 出引导页 → 起后端 → 点「重试」→ 恢复成「衣橱」）
- [x] 在真机上打开、**界面渲染正确**（截屏验证：底部 tab 栏在、品牌一行、无横向溢出）
- [x] **上面那条引导页在真机上同样成立**（2026-10-15 截屏验证）：
      借一个「停服 50 秒后自己恢复」的脚本把后端停掉，手机重载页面 → **引导页正常渲染**；
      后端回来后点「重试」→ 恢复成「衣橱」。
      ★ 这条顺带证明了 **Service Worker 在手机的 `127.0.0.1:8787` 上是真的注册并生效的**
      （否则浏览器连外壳都拿不到，只会出白页）—— 这是 WebAPK 那条之外唯一能证 SW 活着的办法。
- [ ] 「加到主屏幕」后是**独立图标 + 全屏** ← **不成立，如实记录**：
      这台机器上 `pm list packages` 里**没有任何 WebAPK 包**，所以那个主屏图标只是
      **普通快捷方式**，点开仍是**带地址栏**的标签页（有截图为证）。
      要真正的"像 App 一样"，得走 TWA/Capacitor 打包，或换一台允许铸造 WebAPK 的环境。
- [x] 深色模式？**本期不做**（记在待办，别顺手加）

### 允许的字面值（**唯一的**例外清单）

DoD 说"全部来自 token"，但下面几类**刻意保留字面值** —— 它们是**布局/几何常量**，不是视觉 token。
（清单以外出现颜色/字号/间距字面值 = 不合格。**尺寸**字面值只要属于"跟主题无关的布局常量"即可，见下。）

| 位置 | 值 | 为什么 |
|---|---|---|
| 网格最小宽度：`.grid` / `.form-grid` / `.stat-row` / `.detail` | 168 / 190 / 140 / `minmax(200px,300px)` px | 组件自身的最小宽度，与主题无关 |
| `input[type="search"]` | `min-width: 190px` | 同上（输入框的最小可用宽度） |
| `bind.html` 的 `.bind-wrap` / `.qr-box` / `svg` | 520 / 260 / 240 px | 该页自成一体的版式常量 |
| `.status .dot` | `width/height: 6px` | 一个装饰圆点 |
| 触控目标 `min-height: 44px`、`.chip-toggle>span` 的 `min-width: 44px` | 44px | 契约 §4 的硬指标，写死比绕 token 更清楚 |
| `border-radius: 50%`、`aspect-ratio: 1/1` | — | 几何关系，不是设计变量 |
| `margin: 0` / `padding: 0`、`border: 1px solid` | 0 / 1px | 归零与发丝边框 |
| 排版微调 `padding: 1px`、`vertical-align: 1px` | 1px | 发丝级视觉对齐 |
| 行高 `font: …/1.6`、`.steps { line-height: 1.9 }` | 无单位 | 相对值，不需要 token |
| `.tabbar` 的 `backdrop-filter: saturate(180%) blur(20px)` | — | 毛玻璃参数（Apple 的固定手法） |
| `<meta name="theme-color">` 与 manifest 的 `theme_color` / `background_color` | `#f5f5f7` | 这两处**只能用字面值**（meta / JSON 里没有 `var()`）；值必须等于 `--bg` |
| `index.html` 里的 favicon `data:` URI | `%230066cc` | data URI 里没法用 `var()` |
| **间距工具类** `.mt-2/.mt-3/.mt-4/.mt-6/.mb-3/.pointer` | 见 `style.css` | 只给「JS 拼串里一两个元素要个间距」用；**别拿它拼布局** |

> ⚠️ `theme-color` / `theme_color` 这两处是**唯一允许重复 `--bg` 字面值**的地方，
> 改动 `--bg` 时要记得三处一起改（`tokens.css`、两个 `<meta>`、manifest）。

## 7. 设计一致性上踩过的两个坑

1. **录入页的「入库」勾选框漏在触控规则之外** —— 它长在 `.chip` 里面，
   而规则当初只写了 `.toolbar label`。改成 `label:has(input[type=checkbox])` 才覆盖到。
   （教训：**用语义选择器，别枚举类名** —— 枚举永远会漏。）
2. **`.status` 被当成通用类复用了** —— 那个类是为顶栏状态设计的（带 `margin-left:auto`），
   却出现在录入页的预览行里。换成设计系统里真有的 `.chip warn`。

## 8. 留档：被推翻的判断

| v1 的说法 | 推翻依据 | 修正 |
|---|---|---|
| 图片是"不可变内容"，SW 图片走**缓存优先** | 文件名其实是 `<单品id>.<扩展名>`，重传就是**覆盖同名文件** → URL 不变 → 永久命中旧图（而且错得**静默**） | 改**网络优先**；`VERSION` v1→v2 清旧桶 |
| 平板 **640–1024 双列** | 实测 768px 出 4 列；`auto-fill` 自适应本来就比固定列数好 | **不规定固定列数**，交给 `minmax(168px, 1fr)` |
| `--warn: #9a6700` / `--text-faint: #86868b` | WCAG 实算 4.40 / 3.62，都低于正文要求的 4.5 | 改 `#8a5a00` / `#6b6b70`（15 组全达标） |
| 底部栏占位写在 `tokens.css` | 引入顺序改成 token 在后之后，它被 `style.css` 的 `html, body{padding:0}` **静默覆盖**（同特异性、后加载者赢） | 挪进 `style.css` 的手机段 |
| 门禁只看"横向溢出" | 纵向遮挡在结构上量不到 —— 门禁全绿，却有内容真的看不到 | 门禁加 `tabbar_clearance` 判据 |

> 每一条都配了**可机检的证据**（`scripts/cdp_ui_check.js` / `scripts/check_contrast.py`），
> 不是"我觉得改好了"。

## 9. 门禁（每次改前端都跑）

```bash
node scripts/cdp_ui_check.js            # 三视口 + 4 页溢出 + 触控 ≥44px + 底部栏遮挡 + SW + manifest
.venv/Scripts/python.exe scripts/check_contrast.py   # 文字对比度（WCAG AA）
```

前置三样：Node ≥ 18、Chrome 以 `--remote-debugging-port=9333` 常驻（**profile 目录每次新建**）、
应用在 8799 上跑。判据写在脚本头部注释里，失败时对照上面的 DoD。

**两个都是只读的** —— 只导航、量尺寸、截图，不点任何会写数据的按钮。
