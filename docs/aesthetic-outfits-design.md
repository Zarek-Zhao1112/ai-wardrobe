# §20 完整审美方案驱动搭配（2026-10-23）

用户确认：每套审美同时安排配色、轮廓、材质、图案、层次，然后去衣橱找衣服；不要适用场合。该确认覆盖旧§10推荐以场合和正式度多样性为依据的相关规定。

首版两套完整方案：自然松弛、利落清爽。每套有稳定id、版本、核心特征、可变化部分、五维目标和公开来源。它们是编辑整理的审美方法，不代表用户已喜欢，也不是模型训练结果。颜色、版型等只作为软匹配；不设三色上限、松紧禁配或性别限制。季节仅保留当前衣橱可穿性过滤。

生成链路：选完整方案→按同一方案给各穿衣角色召回衣服→真实基础套装+有界可选外套/明确配饰→五维关系评分→核心单品多样化短名单→DS4.1在既有编号内比较→保存与展示。场合参数仅为旧调用保留，值不参与偏好、模型提示或新搭配记录；正式度也不参与排序或强制多样性。个人既有颜色/版型等偏好仅作辅助。保留已有偏好数学公式，不修改历史数据。

基础组合仍为上装+下装+鞋或连身+鞋。外套最多一件、明确配饰最多一件，均可不选，不改变衣橱组合数/缺口分析。内衣、其他/未知配饰不自动添加。召回保留探索名额，短名单覆盖不同核心衣服，不能全部只是同一上下装换鞋。

每套保存审美目标及五维评估快照。评估区别有依据、近似替代、信息不足；缺失不是冲突。材质成分不等于质感，裤长不等于人体比例，商品图/标签不足以断言显高显瘦、三七比例、实际保暖、光泽垂坠。AI比较看到补充的品类/图案/风格/裤长与评估，受控返回候选编号；本地五维依据独立于AI理由，AI不可用仍显示本地方法结果。

本轮文件分工（主agent统一写入）：
- 新增`app/services/aesthetics.py`：方案目录、召回/有界组套/五维评估/短名单。
- `recommend.py`：接入新链路，保持真实单品和编号校验；`routes/outfits.py`增加方案目录和选择参数。
- 明确限定共享文件改动：`schema.py`增加v3迁移，仅新增outfits.aesthetic_snapshot TEXT；`models.py`仅给OutfitOut增加可空aesthetic字段，保证详情响应不丢快照。不改config/main/taxonomy。
- `web/js/view-outfits.js`、`api.js`、`style.css`、`sw.js`：方案选择与完整说明，移除场合和置信度百分比，展示事实依据和生成时快照。失败保留上一结果，busy及挂载身份隔离迟到响应；反馈“换一套”改为准确的“先不选”，本轮不实现局部换衣。

数据：v2→v3增量迁移，旧搭配快照NULL，不补成当前方案；已有衣服、照片、草稿、场合历史和反馈不删除。新生成scene=NULL。只在系统临时库测试迁移，真实手机覆盖安装前后核对衣橱/草稿哈希。

验证：内存与临时库的方案切换确实改变候选、冷启动覆盖、未知属性、外套与配饰边界、场合不参与、编号越界、无模型、历史快照与v2迁移；浏览器390/768/1440、生成失败/切页/改选/双击竞态；pytest、smoke83、对比度15；两路只读审查；APK解包核对与真机草稿保留。模型真实性试验仅合成衣橱，不能宣称审美准确率。

## §20.1 八套方案（2026-10-23）

在原两套v1之外增加同色层次（tonal）、复古工装（heritage）、运动混搭（sport_mix）、街头廓形（street）、柔和轻盈（soft）、撞色焦点（color_pop），均为v1的编辑方案。每套拥有五维目标及显式召回、颜色、图案、版型、层次配置，不能把新方案隐式归入旧clean分支。旧两套的目标、公式及召回顺序保持v1语义。

同色层次强调同色系和可选层；复古工装利用牛仔/夹克/靴及复古标签之间的关系；运动混搭比较运动元素与衬衫/西裤等基础单品共同出现；街头廓形强调宽大衣服与球鞋/靴的组合；柔和轻盈用浅色标签、舒展线条和较少叠层作近似尝试；撞色焦点比较基础色与重点色的关系，不奖励单纯增加颜色数量。上述均为软偏好，缺少对应单品时允许近似结果，不引入性别或适用场合。运动套装仍遵守全局HOME_LIKE排除，避免改变组合数口径。

材质继续仅展示已填成分、不评分；浅色标签不能证明低饱和度、轻薄或柔软。整套类型关系纳入层次的事实说明，不另造用户维度。全部方案保持未知中性值和完整评分分母，不按颜色数或图案数硬淘汰。

前端改为原生details方案选择器，默认显示当前名称和简介，展开可选八套；手机单列、平板两列、桌面四列，选中后收起并把焦点还给summary。保留完整五维说明、生成参数快照、历史快照与请求隔离。改动限于aesthetics.py、view-outfits.js、style.css、sw.js及测试/文档，无数据库迁移。

验证增加六套竞争候选的真实选择、召回差异、运动混搭整套关系、旧两套数值/排序回归、各方案未知与快照保存；UI验证展开可达、收起高度、焦点归位、八套切换和异步隔离。其余门禁和真机覆盖安装数据核对沿用§20。

## §30 搭配卡与实时试衣面板（2026-10-28）

用户确认outfit-live-preview。搭配每次突出一套真实单品，以受控槽位安排平铺构图；保留八审美、季节、3/5套、本地排序/AI比较、完整依据、历史和反馈。五套窄屏分页换行，保持44px触控目标。反馈按ID保存在当前deck，翻页或迟到响应不丢选中状态，同ID请求期间重建卡片仍禁重入。

生成失败保留已有结果；离开后回页仍复用同次请求，成功直接展示新结果。试衣打开时保存deck快照，回调只更新同一deck，避免新结果较短时被旧索引破坏。

实时试衣玻璃面板支持真正的摄像头视频预览、镜头切换、单品参考和换套，只有用户点击才申请视频。停止/关闭/后台/路由切走/销毁立即停轨；等待授权或播放期间取消后，迟到流也关闭。同hash历史先消费面板，退出恢复模糊/滚动/焦点。

本阶段未配置实时视频AI供应商，清楚显示“实时试衣服务尚未连接/当前原始画面”，AI按钮不可用；不上传视频、不保存帧、不装示意模特、不显示假换装结果。实际视频模型与多件还原能力按用户要求留待后续接入测试。DS4.1等既有模型与账号不变。Android原生权限仅授予前台当前127.0.0.1:8787页面的单一视频资源，不申请录音，后台迟到请求拒绝。


### §30.1 搭配单品不互相遮挡（2026-10-28）

搭配卡取消绝对定位拼贴。上衣/外套、下装/连身分别在正常流网格列中排列，鞋与配饰在独立行；未知槽位进入鞋饰区域，不丢单品，重复槽位自动增行。每件图片contain完整显示，图片盒与点击区域均不相交。件数说明独立占行，不压在照片上。卡片随件数自然增高，页面可滚动至底栏上方，不裁掉外套、裤脚或额外配饰。保持真实图片、原单品ID、推荐请求、反馈与试衣快照的契约，不改模型、账号、数据库或图片文件。

验收覆盖3/4/5件、连身、重复/未知槽位、无图、320/390/768/1440视口，量单品图片盒两两无重叠且在卡片内、每个真实单品链接可达、长文案与底栏间距；Android12/WV96真机只读核查，不启动模型或摄像头。SW v43。
