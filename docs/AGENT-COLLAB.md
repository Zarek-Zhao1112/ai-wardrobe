# 多 agent 协作

**讨论 → 设计 → 开发 → 审查**。四段，每段有产出、有结束判据。
读者：派活的（主对话）和被派的（审查 agent）。

---

## 一条铁律

**同一时刻只有一个写入方**（主对话）。其余 agent 一律只读。

两个 agent 同时改文件 → 谁改的、改没了什么，事后查不清。
所以审查 agent 的 prompt，第一句永远是「**绝对不要修改、创建、删除任何文件**」。

## 四段

| 段 | 谁做 | 产出 | 结束判据 |
|---|---|---|---|
| **讨论** | 主对话 ↔ 用户 | 一句话问题定义 + 已有证据（`文件:行号`、命令输出） | 用户说「就这个」 |
| **设计** | 主对话 | 改哪几个文件、每处为什么、怎么验证 | 用户点头（或明说跳过） |
| **开发** | 主对话（唯一写入） | diff | 自己说得清每一行 |
| **审查** | 2 个只读 `Explore`，**并行** | 问题清单 | P0/P1 修完并复测，P2 记待办 |

审查派两个，不是两个都看全部 —— **按栈拆**（壳一个 / 业务一个，后端一个 / 前端一个）。
合在一个 prompt 里，agent 只会挑自己熟的那半边看。

**只有注释、文案、单个常量可以跳过审查。** 动了逻辑或契约就要审。

## 审查 prompt 的 5 个必备项

少任何一个，回来的都是复述实现。

1. 开头一句「**绝对不要修改、创建、删除任何文件**，只读代码」
2. **具体文件路径 + 行号范围** —— 不是「看看这个项目」
3. **怀疑点清单**，一条一条编号 —— 不是「审查一下」
4. **目标环境**（机型 / 浏览器 / OS）—— 有的 bug 只在特定环境成立
5. **输出格式**：P0/P1/P2 分档，每条给 `文件:行号` / 触发条件 / 建议改法

再加一句：**「没问题的怀疑点也要写『已核查，不成立 + 原因』」**。
不写这句，分不清他是真查过还是糊弄过去。

## 缺陷怎么定档

| 档 | 判据 | 处置 |
|---|---|---|
| **P0** | 会崩 / 功能完全不可用 / 数据不可逆丢失 | 当场修，不修不提交 |
| **P1** | 换个场景就坏（机型、取消操作、并发、重启） | 当轮修；修不完写进 `HANDOFF.md` |
| **P2** | 能跑但难受（慢、文案与事实相反、难维护） | 记待办，不阻塞 |

结论**不许只挑自己想改的**：P0/P1 全修；P2 逐条明确「修」或「不修 + 理由」。

## 反模式（都真踩过）

| 反模式 | 后果 |
|---|---|
| 只看源码不看产物 | 源码改了、装的还是旧包。判据只能是 **dex 搜特征字符串 / 解压 `assets/*.imy` 再搜** |
| 信既有测试 | 参数写反 → `rowcount` 恒 0、断言恒真，测试长期假绿 |
| 写了「已核查」但不写原因 | 下次重查一遍，或者直接把真问题漏掉 |
| 审查里顺手「帮你改了」 | 破铁律，diff 失控 |

## 证据

跟 `AGENTS.md`「报告工作时的规矩」同一套：**不说"已完成"，给命令输出或文件指纹**；
没验证标"未验证"，是推断写"推断"。
