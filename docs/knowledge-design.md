# P4 知识库技能 · 实现设计

> **用途**：P4 的实现依据。需求与边界都在本文件；本文件只写"**怎么实现**"
> 以及实现时必须照做的规格。
>
> **P4 = 在微信里聊学习 → 助手读你的第二大脑笔记陪你聊 → 把结论写成新笔记存回去。**

---

## 1. 需求（用户逐条确认，2026-10-05）

| # | 需求 |
|---|---|
| 1 | 微信 ClawBot 从"穿搭顾问"扩展出"学习入口"：能读第二大脑的笔记，陪着聊 |
| 2 | 说"我想学 X" → 列出库里相关笔记；库里没有 → **建议开新领域，用户点头才建** |
| 3 | 三种开场：① 点名主题 ② 让助手挑 ③ 直接提问（助手拿全库当背景答） |
| 4 | 聊完产出**完整笔记**；但**一篇别太长** —— 拆成 1–3 篇聚焦笔记 |
| 5 | **先发预览**（篇目 + 文件名 + 落点 + 大纲 + 预计用时），用户回"落"才真写 |
| 6 | **只新建，绝不修改已有 33 篇**（含地图页）—— 整理由用户自己做 |

闭环：`你说"想学X" → 它列相关笔记 → 聊 → 生成 1–3 篇 → 发预览 → 你说"落" → 写进库`

## 2. 分层（不许破坏的边界）

```
微信 ──► app/channels/clawbot.py ──► app/services/conversation.py ──► app/services/knowledge/*
        （iLink 协议层）              （会话状态机 + 意图路由）        （本技能的业务层）
```

判据沿用 `p3-design.md` §2：`conversation.py` **不许 import httpx**、不拼 URL、不出现 iLink 端点名。
`knowledge/` 包同样**不许 import httpx** —— 它只跟文件系统和 LLM 层打交道。

**无需新增 HTTP 路由**：`main.py` 的 lifespan 已把 `ClawBotWorker` 接到 `conversation.handle`。

## 3. 外部知识库的事实（实测，实现必须按这个来）

根目录来自 `config.KNOWLEDGE_VAULT_DIR`（默认空字符串 = 整个技能禁用）。

### 3.1 目录结构（33 篇 md）

```
索引.md                     ← type: map，唯一日常入口
学习路径总览.md
领域/
  Web开发/        地图 + 01~07 共 8 篇
  编程与系统/      地图 + 5 篇
  金融投资/        地图 + 4 篇
  通用方法论/      地图 + 1 篇
  自我与职业/      地图 + ①~⑤
inbox/收件箱.md
资源/                       ← 空目录
归档/                       ← 空目录（不在 P4 范围内）
模板/{笔记规范.md, 图谱配色说明.md}
```

### 3.2 ⚠️ 库里并存 **3 套**写法（不是 1 套）

| 体系 | 篇数 | frontmatter 字段 | 收尾章节 |
|---|---|---|---|
| 新式知识笔记（`type: permanent`） | 23 | `type / tags / aliases / created / source / note` | 8 篇 `## 关联`、7 篇 `## 附：延伸学习线索` |
| 旧式（Web开发 01–07、自我与职业 ①–⑤） | 12 | `title / category / difficulty / status` | `## 关联` |
| 地图 / 索引 / 模板 / 收件箱 | 8 | 极简或无 | — |

**决定：新笔记「就近对齐」** —— 按**目标领域的多数派**写法生成（通常是新式）。
落点是 Web开发 / 自我与职业（旧式领域）时，**沿用该领域的旧式字段**。
判定方式：扫描同目录兄弟笔记，看 `type:` 多还是 `category:` 多。

### 3.3 新式笔记的骨架（逐字核过）

```yaml
---
type: permanent
tags: [关键词1, 关键词2, 领域/金融]        # 领域标签放最后一位
aliases: [别名]
created: 2026-08-30
source: 与 AI 助手对话学习整理 + 具体来源
note: 只讲…。通用方法见《投资方法论·估值与择时》，因子框架见《红利低波·因子与专题》。
---
# 主标题 · 副标题
```

⚠️ 三个最容易写错的地方：

1. `note` 字段里引用其它笔记用**书名号《》**，**不是** `[[wikilink]]`。正文里才用 `[[]]`。
2. H1 是 `# A · B`（**空格 + 中点 + 空格**）；主标题内部不加空格。
3. 领域标签放在 `tags` 数组的**最后一位**。

### 3.4 领域标签：3 个领域与目录名不符（**按实测值写**）

| 目录名 | 文档（图谱配色说明）写的 | tags 实测 | 新笔记写 |
|---|---|---|---|
| Web开发 | `领域/Web开发` | `领域/Web开发`（7） | `领域/Web开发` |
| 编程与系统 | `领域/编程与系统` | **`领域/编程`**（5） | **`领域/编程`** |
| 金融投资 | `领域/金融投资` | **`领域/金融`**（4） | **`领域/金融`** |
| 通用方法论 | `领域/通用方法论` | **`领域/方法论`**（1） | **`领域/方法论`** |
| 自我与职业 | `领域/自我与职业` | `领域/自我与职业`（6） | `领域/自我与职业` |

规则：**同目录多数投票**（数兄弟笔记的 `领域/*` 取值，取最多的那个）。
⚠️ 文档与实测不一致这件事**不自动修**，只在体检报告里列出。

### 3.5 篇幅

实测单篇 9360–14589 字符（全库 117653）。
但 P4 生成的新笔记目标 **3–5k 字符/篇**，拆 **1–3 篇**（用户定调："尽量不要让一篇笔记太长"）。

## 4. 会话状态规格（本文档存在的主要理由之一）

`conversation_state.state` 是 JSON blob，**加 key 免迁移**（`_empty_state` + `setdefault`）。

```jsonc
"pending_note": {
  "topic": "RSI 与 BIAS 的区别",
  "mode": "learn | ask",                  // learn=点名学某主题；ask=先提问
  "related": ["沪深300·宽基与算法设计"],    // 命中的已有笔记（只存文件名，不存正文）
  "domain": "领域/金融",                   // ★ 实测值（见 §3.4），不是目录名
  "dir": "领域/金融投资",                  // 落盘目录（相对 vault）
  "new_domain": false,                    // true = 该目录还不存在，需用户点头才建
  "plans": [                              // 1–3 篇
    {
      "filename": "RSI与BIAS·振荡指标辨析.md",
      "title": "RSI与BIAS",
      "subtitle": "振荡指标辨析",
      "aliases": ["..."],
      "tags": ["..."],
      "sections": ["一、定义与计算", "二、信号差异"],
      "bodies": {"一、定义与计算": "..."},  // 逐节填充后回填
      "intro": "...",                       // 目标 / 一句话定位
      "outro": ["- ..."]                    // 延伸学习线索
    }
  ],
  "stage": "awaiting_outline | awaiting_save",   // 预览前 / 预览后等确认
  "at": "2026-10-05T23:30:00"
}
```

**三条硬约束**：

1. **`pending_note` 与 `pending_draft`（衣物草稿）强制互斥** —— 两个草稿同时存在时，
   用户说「落」系统不知道该落哪个（静默歧义）。开新流程前先清另一个。
   ⚠️ 项目里**没有**现成的互斥辅助函数（现有草稿清理是 `_dispatch` 内联的 `dropped`）→ 本技能自己写。
2. **TTL = 6 小时**（`NOTE_TTL`）。理由：讨论 + 分段生成远超衣物草稿的 30 分钟（`DRAFT_TTL`），
   但也不能无限期 —— 隔天的「落」不该落到昨天的方案上。过期即清空。
3. **只存必要信息**：`related` 存文件名而非全文；长正文只在 `bodies`（拼装需要，无法回避）。

## 5. 意图分类规格

### 5.1 新增意图与词表

```python
_LEARN       = ("我想学", "想学", "学一下", "讲讲", "讲一下", "了解一下")
_LEARN_GUARD = ("衣橱", "单品", "这件", "这条", "这双", "搭配", "怎么穿")   # 命中则不判 learn
_BROWSE      = ("随便挑", "随便聊聊", "最近学点", "学点什么", "你挑一个")
_NOTE_SAVE   = ("落", "写入", "写吧", "存吧", "保存", "入库", "记下来")
_NOTE_DROP   = ("算了", "不落", "不写", "取消", "不用了")
```

### 5.2 插入位置（**顺序即语义**）

```
空 → unknown
has_draft 块（衣物草稿，最高优先）
has_note 块（笔记草稿：save / drop / 其余当讨论）
序号+态度 → 兜底块
_GAP → _BUY
>>> learn / browse <<<          ← ★ 必须在 _MATCH 与 taxonomy 兜底之前
_MATCH → swap → like
_is_new_item → describe
taxonomy 兜底 → unknown
最后：ask（全落空 且 含 ？/是什么/为什么/怎么/区别/如何）
```

### 5.3 撞词分析（逐条比对现有词表得出）

| 风险 | 处理 |
|---|---|
| 「我想学**怎么搭配**」命中 `_MATCH`（含"搭配"） | `learn` 排在 `_MATCH` 之前 |
| 「我想学**卫衣**怎么挑」被 L202 兜底判成 `describe`（品类词命中） | `learn` 排在兜底之前 |
| 「讲一下**这件**怎么穿」 | `_LEARN_GUARD` 命中 → 不判 learn |
| 「介绍」单独用太宽（"介绍下你自己"） | **不单独收"介绍"**，必须带"一下/想了解/想学" |
| `ask` 吞掉正常对话 | 仅**末位兜底**，且必须含疑问特征词 |

## 6. 生成规格

### 6.1 拆篇（用户的明确要求）

**1–3 篇**，每篇单主题，单篇目标 3–5k 字符。
理由：库里现有组织本来就是"一个领域多篇、各讲一个子主题"（`编程与系统/` 5 篇、`Web开发/` 8 篇），
单篇 9–14k 字符反而是异类；拆开还能让单次等待更短、内容更聚焦。

### 6.2 四步分段（对抗 `MAX_OUTPUT_TOKENS = 2048`）

| 步 | 调用 | 产物 |
|---|---|---|
| ① 拆题 | `chat_json` | `[{title, subtitle, aliases, tags, sections:[{heading, points}]}]`，1–3 篇 |
| ② 逐节 | `chat_text` × N | 每节 800–1200 字符 |
| ③ 收尾 | `chat_text` × 1 / 篇 | 「目标 / 一句话定位」+「延伸学习线索」 |
| ④ 拼装 | **纯 Python** | `assemble_note()` 拼 frontmatter + 正文 |

**结构绝不由模型产**：frontmatter 字段、章节顺序、分隔符、收尾小节标题，全部由 Python 写死。

### 6.3 防跑偏

- 每节的 prompt 都带：该篇完整大纲 + 已写各节 ≤200 字提要 + 全局约束 + "**本节只写第 N 节**"
- `temperature=0.4`
- 产出后校验：节数 = 大纲数 / `[[…]]` 目标必须 ∈ 已有 33 篇（否则**剥掉**，不许凭空造链接）/
  字数区间 / 结尾是标点
- 违规**单节重试一次**；再违规就跳过该节并如实告知用户

## 7. 写盘安全（防"写坏真实库"）

1. **目录只来自白名单**：已存在的 `领域/<已知领域>`，或**经用户点头**的新目录。
   用户输入的主题只用来决定**文件名**，永远不参与拼目录路径。
2. `sanitize_name`：去掉 `\ / : * ? " < > |`、控制符、首尾点与空格、`..`；限长 80；补 `.md`。
3. **路径越界断言**：落盘前 `target.resolve()` 必须 `startswith(vault.resolve() + os.sep)`，
   否则抛错并友好回复（防 `..\..\` 之类）。
4. **只新建不覆盖**：目标已存在则加后缀 `-2 / -3` …（上限 50），**永不覆盖**。
5. **原子写**：临时文件写在**目标同目录**再 `os.replace`（跨盘不用系统 temp，规避 C: → X: 的坑）。
6. `new_domain` 仅在用户预览点头后才 `mkdir(parents=True, exist_ok=True)`，**只建一级**。

**默认最安全**：`KNOWLEDGE_VAULT_DIR` 为空 = 整个技能禁用。

## 8. 挂载与双链策略（在"不动 33 篇"的边界内）

1. **正向链**：新笔记正文写「所属领域：[[金融投资地图]]」+「相邻笔记：[[A]] · [[B]]」
   —— 只从新文件指向旧文件，**不违规**。
2. **反向链无需改文件**：Obsidian 的 Backlinks 与图谱**天然双向** ——
   新笔记里出现 `[[A]]`，A 的反向链接面板与图谱会自动显示。
3. **地图页挂载**：默认**不自动追加**（那会改到地图这篇旧文件）。
   预览回复里附一行可复制样板 `- [[新笔记]]`，由用户自己粘。
4. **标签不一致**不自动修，只出**只读体检报告**。

**相邻笔记的选法**：从检索命中篇里取（最多 2 篇），按词法得分降序；
一篇都没命中时，取同领域的最近一篇。

## 9. 波次与门

每波固定三门：`smoke_test.py` 全绿 + `pytest` 全绿 + 真实库 `data/wardrobe.db` 指纹不变。

| 波 | 内容 | 验收门 |
|---|---|---|
| **W0** | 本设计 + `config.py` 加 `KNOWLEDGE_VAULT_DIR` + 快照 | 本文件定稿；smoke 61/61 未回归 |
| **W1** | `knowledge/` 包：frontmatter / catalog / retrieval / 文件名清洗（**零 LLM**） | `pytest tests/test_knowledge.py` 绿；smoke 加节后全绿 |
| **W2** | `conversation.py` 接入 `learn`/`browse`；无命中→建议新领域（不建） | smoke 全绿；`test_p4_regressions.py` 绿 |
| **W3** | `pending_note` + 拆题 + 预览回复 | FakeLLM e2e：learn→预览→改→算了 |
| **W4** | 逐节生成 → 拼装 → 安全写盘 | e2e 只写**临时 vault**；越界输入被拒 |
| **W5** | 双审查（规格核对官 + Bug 猎手）+ 修；体检报告 | 33 篇真实 md 的 sha256/mtime 全部不变 |

## 11. 不在 P4 范围（明确排除，别顺手做）

- **修改已有笔记**（含补章节）→ 用户明确要求"先只做新建"
- **自动追回地图页**（`- [[新笔记]]`）→ 用户选择自己粘
- **自动修标签不一致** → 只出体检报告
- **收件箱整理 / 归档** → 用户自己做
- **图片/照片输入** → 依赖视觉模型与媒体解密（P3 第二阶段的事）
- **主动推送**（定时提醒复习）→ P5 候选
