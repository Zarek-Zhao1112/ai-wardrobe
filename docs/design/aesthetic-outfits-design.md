# §20 完整审美方案驱动搭配（2026-10-23）

当前六方案与审美指南以文末§35为准（§34 的三张样图已被撤回），前文保留历史语义。

用户确认：每套审美同时安排配色、轮廓、材质、图案、层次，然后去衣橱找衣服；不要适用场合。该确认覆盖旧§10推荐以场合和正式度多样性为依据的相关规定。

首版两套完整方案：自然松弛、利落清爽。每套有稳定id、版本、核心特征、可变化部分、五维目标和公开来源。它们是编辑整理的审美方法，不代表用户已喜欢，也不是模型训练结果。颜色、版型等只作为软匹配；不设三色上限、松紧禁配或性别限制。季节仅保留当前衣橱可穿性过滤。

生成链路：选完整方案→按同一方案给各穿衣角色召回衣服→真实基础套装+有界可选外套/明确配饰→五维关系评分→核心单品多样化短名单→DS4.1在既有编号内比较→保存与展示。场合参数仅为旧调用保留，值不参与偏好、模型提示或新搭配记录；正式度也不参与排序或强制多样性。个人既有颜色/版型等偏好仅作辅助。保留已有偏好数学公式，不修改历史数据。

基础组合仍为上装+下装+鞋或连身+鞋。外套最多一件、明确配饰最多一件，均可不选，不改变衣橱组合数/缺口分析。内衣、其他/未知配饰不自动添加。召回保留探索名额，短名单覆盖不同核心衣服，不能全部只是同一上下装换鞋。

每套保存审美目标及五维评估快照。评估区别有依据、近似替代、信息不足；缺失不是冲突。材质成分不等于质感，裤长不等于人体比例，商品图/标签不足以断言显高显瘦、三七比例、实际保暖、光泽垂坠。AI比较看到补充的品类/图案/风格/裤长与评估，受控返回候选编号；本地五维依据独立于AI理由，AI不可用仍显示本地方法结果。

本轮文件分工（主agent统一写入）：

## §20.1 八套方案（2026-10-23）

验证增加六套竞争候选的真实选择、召回差异、运动混搭整套关系、旧两套数值/排序回归、各方案未知与快照保存；UI验证展开可达、收起高度、焦点归位、八套切换和异步隔离。其余门禁和真机覆盖安装数据核对沿用§20。

## §35 审美只用一种视觉：平铺静物（2026-11-03）

§34 的「三张模特样图」不再出现在界面上。原因不是审美偏好，是两套视觉语言并存：卡片是平铺静物，点进去是同一个模特、同一面墙、同一站姿的全身照，一进一出像换了个页面。18 张样图彼此也高度同构（同人同墙同光），缩略图尺度上「不同方向之间的距离」和「同一方向内部的距离」是一个数量级，摆在卡片上区分不出方向。

现行：六套各一张平铺静物封面 `cover-<id>.webp`（900×1299，`aesthetic_catalog.COVERS` 注入 `cover`），首页卡、选择网格、详情页首屏**共用同一张**，不设 `aspect-ratio` 覆盖（`900/1299` 就是原图比例，任何更宽的取景都会切掉最下面那双鞋）。

详情页因此不再有单图页与大图翻页。三套具体穿法改为文字条：序号 + 标题 + 单品清单，展开是五条安排要点（配色/轮廓/材质/层次/呼应），信息一条没少，图一张不多。搭配依据面板不受影响。

代价：`examples[].image` 与 18 张 webp 仍在数据与仓库里（历史快照与 `coverFor()` 回退还依赖它），但 UI 不再渲染；APK 里这部分体积暂时留着，未做裁剪。

## §36 添置这条线也换了（2026-11-03）

§35 只改了「搭配」。添置首页的「审美方向」行仍读 `examples[].image`：三张模特样图各塞进 25×52 的格子（原图 2:3，`object-fit:cover` 后横向再裁 28%），三个人同一张脸同一个站姿，实际观感是三条人形切片。添置助手顶栏那个 42×34 的小头像同理。

现在两处都用 `cover-<id>.webp`：首页行 36×52（0.692 ≈ 原图 0.693，零裁切，整套平铺完整），顶栏 30×42 竖框。

新增 `coverImage(profile)`：只返回校验过的 cover，**不回退示例人像**。`coverFor()` 的人像回退是给历史快照留的，添置侧不能走那条路 —— 一旦 cover 缺失，宁可整块不渲染，也不把模特放回来。

至此五处（首页卡 / 六宫格选择 / 详情页首屏 / 添置行 / 助手顶栏）共用同一张封面，全站只有一种审美视觉。

## §37 添置行的缩略图改成「鞋 + 裤脚」局部（2026-11-03）

§36 把添置行换成竖封面塞进 36×52。尺寸对得上（0.692 ≈ 原图 0.693，零裁切），但 36px 下整叠缩成一条：领口 → 白 T → 裤子 → 鞋，正好是一个人的比例，看着像没头的人。

试过的三种裁法，只有最后一种成立：

| 裁法 | 结果 |
|---|---|
| 上装（方形 52×52 或横版 74×52） | 这六张都是「敞开外套里一件白 T」，裁上装等于裁一个胸口，比整叠更像人 |
| 整条裤子（36×52） | 框不住：鞋与裤脚在水平方向重叠（鞋在左、裤脚在右），左上角必然切到鞋头；下端又必然带出上衣下摆。框出来的像"手滑裁歪了" |
| **鞋 + 裤脚（74×52）** | 静物，没有身体链条；鞋型本身也是风格信号（德比 / 乐福 / 布洛克 / 球鞋 / 平底） |

取景框 `scripts/assets/crop_aesthetic_thumbs.py` 里的 `BOX = (180, 990, 620, 1299)`，440×309（1.424），对齐显示尺寸 74×52。六张封面排布几乎一致，一个框通用。产物 `thumb-<id>.webp` 六张共 111 KB。

`aesthetic_catalog` 由 `COVERS` 推 `thumb-<id>.webp` 注入 `thumb`；前端 `thumbImage()` 先取 thumb、退到 cover、再退到空（空则不渲染，不退回人像）。`coverImage()` 与 `coverFor()` 不动 —— 搭配页卡片、六宫格、详情页首屏仍是竖封面，只有横格子用缩略图。

**尺寸不是调出来的，是试出来的**：36 / 40 / 44 / 48 四档都做了 1:1 对比，放大只会让人形轮廓更清楚，问题不在大小而在"框里装了什么"。

## §38 添置行改回整套竖封面（2026-11-03）

§37 的「鞋 + 裤脚」局部解决了「像人」，但代价是看不到整套 —— 一行小图只剩一双鞋，用户点开前无法判断这是哪一套。用户明确要求「要看到整套」。

现在：竖框 **60×87**（60/87 = 0.6897，原图 900/1299 = 0.6928，`cover` 裁切 < 1px，等于零裁切），行高 80 → 111。用 `coverImage()`，拿不到 cover 整块不渲染。

§37 里「36px 整叠像没头的人」的判断要修正：**那是尺寸不足的误读，不是构图缺陷**。40px 以下细节全部丢失，只剩「领口→白T→裤→鞋」一条纵向剪影；放到 60px 宽，袖子是摊平的、裤腿是分开的、鞋是斜摆并排的，读作平铺。44 / 52 / 60 三档 4 倍放大逐一比对过，60 是最能看清整套又不压过文字的一档（68×98 行高 122，卡片显得笨重）。

六张封面按「穿着展开」摆（flat lay 通行做法），必然带一点人形轮廓 —— 那是它能表达「整套怎么穿」的代价。要彻底消掉只能重出图改成叠放，本轮不做。
