# §35 衣物搭配信息（2026-10-29，用户确认精简预览）

用户确认 garment-profile-preview 精简版：多图自动识别和平铺后逐件确认，默认显示配色、轮廓、图案、穿法四格，可展开完整只读信息；不展示“看看识别依据”，不恢复编辑或穿着记录。保存与跳过位于展开内容后，随内容滚动。衣物详情复用同一信息组件，保留红色喜欢、用这件搭配与确认删除。

## 数据与识别

沿用schema4、ItemCreate/ItemOut的tags字典和IndexedDB v1，在tags.visual_profile保存版本化衣物信息。不增加数据库列，不改现有品类、账号、DS4.1或平铺模型。旧衣/旧草稿没有新档案时显示已有基础属性与未知提示，读取不触发收费补识别。

档案包含version、item_type、image_hash、attributes。每个属性为受控value、source（image/product_text）和certainty（clear/approximate）；unknown、非法来源或未知枚举丢弃，不接收自由提示文字。字段包括tone、chroma、volume、silhouette、body_length、neckline、sleeve_length、closure、pattern_scale、pattern_density、surface、sheen、wearing_options。照片中的颜色、体量、表面表现按近似线索处理；body_length只接受对应商品文字的明确长短信息，不从平铺图或人体比例猜测。材质成分、实际尺寸、厚度、触感、功能和垂坠不由新档案臆断。

识别继续使用原始照片/对应商品截图及内部目标选区，生成的平铺图只用于展示。服务端绑定本次实际识别图片指纹和品类；品类/图片不匹配时不采用旧档案。模型不能提供路径、指纹或任意tags。队列单独合并受控档案；重新识别未给出新档案时清理旧档案，其他自定义tags保留。pending保存冻结完整属性与展示图，幂等重试不更换内容。自动打标只在既有tags下更新本命名空间，保留_photo_import等元数据。

冲突字段接受属性名、visual_profile.属性名及visual_profile.attributes.属性名，统一剔除并返回受控冲突说明。无图案时不采用图案密度；基础图案与图案面积矛盾，或基础松紧与体量矛盾时，新线索保守留空。只填空属性在写锁内先合并当前档案，再校验门襟/体量等依赖；校验依据本次实际采用的基础属性。未知未来版本保持原样，不尝试解析或覆盖。

## 消费与穿法

六套现行审美使用v2评估以区分已有历史快照；旧八套v1公式和历史结果保留。新信息同时进入候选召回、整套评估、模型重排和添置上下文/指纹。未知字段保持中性，不作为硬性不合适；表面外观与成分事实分开，不能用棉/涤纶推断柔软、垂坠或机能。

穿法为条件性建议。普通基础角色仍保持唯一；只有结构信息明确、允许敞开叠穿的衬衫/开衫/马甲与可作内搭的上装，且两者体量线索支持内外关系时，才允许作为一内一外尝试。每套至多一个外层，不直接放开重复top；连身与上下分体、重复下装/鞋、同类配饰继续拒绝。建议购买的新上装没有实际衣物档案时按基础上装处理，不能由自由文案将其变成外套。未知条件不自动补猜，实际余量仍需试穿确认。

## 验收

系统临时目录中的合成衣橱与假模型验证字段白名单、来源/品类/图片一致性、命名空间合并、草稿和pending保留、旧数据兼容、未知中性、召回/排序/模型上下文、穿法冲突和失败幂等。真实浏览器检查四宽度、逐件切换、异步更新时展开/焦点/滚动、只读录入、未知品类重新识别/跳过、详情与离线资源。两个只读审查分别覆盖后端数据与前端生命周期。APK逐项核验并覆盖安装，手机仅做只读检查与数据指纹比对，不自动重识别旧衣或调用真实模型。

实测结果：pytest1193通过、1跳过，烟雾83/0、对比15/0；队列内存边界14项、真实独立浏览器15项及通用三视口门禁通过。APK核对71个web文件和51个后端模块，手机实装摘要与产物一致。SW v49完整预缓存70项；真机26件衣物、15套历史、63个图片文件及数据库/草稿/配置摘要在安装与只读验收前后一致。两路审查通过，无未处理的P0/P1。后续首次真实录入会使用新识别结构，本次验收未消耗真实模型额度。
