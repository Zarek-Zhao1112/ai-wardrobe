# 跨项目复用提示词：按现有项目制作效果图与交互原型

把下面整段提示词复制到另一个项目中使用。建议先在目标项目的根目录打开 AI 编程助手，再粘贴提示词。

```text
请基于当前项目，制作一套与项目现有产品保持一致的网页效果图和可交互原型，供我们预览、讨论和确认设计。

## 总目标

这是对当前项目现有界面和行为的还原与延伸，不要另起炉灶做一套风格相似但与项目不一致的概念稿。先阅读项目代码、已有页面、样式、路由、资源、说明文档和可运行方式，再决定如何实现。

最终在一个网页里提供两种查看方式：
1. **界面效果图**：展示从当前项目真实前端生成的静态截图，覆盖主要页面和关键交互状态。
2. **交互预览**：尽量复用项目现有的页面、样式和交互代码，让我能在浏览器里点击、填写、切换和查看结果。

两种查看方式放在同一个工作台网页中，并能方便地切换。页面布局、文案、色彩、间距、组件、交互反馈和内容都应以当前项目为准。不要用临时的通用仪表盘、占位卡片或自行设计的品牌元素替代现有界面。

## 开始前先做

1. 检查项目结构，找出实际运行的前端入口、主要页面、路由、组件、样式、图片和字体资源。
2. 了解本地启动方式、技术栈和已有测试/构建命令；优先沿用项目已经使用的工具。
3. 根据代码梳理主要页面，以及从页面进入的详情、弹窗、抽屉、表单步骤、加载中、成功、失败、空状态等重要交互状态。
4. 如有信息不确定，先基于代码和现有界面作合理推断，并把推断清楚标为“待确认”；只提出会影响实现方向的关键问题，不要因为小细节停下来。
5. 先简要告诉我你发现的页面、交互路径和实现方案，然后继续完成原型；如果存在会导致大范围返工的重大歧义，再先向我确认。

## 效果图与交互预览要求

- 静态截图必须由当前项目的真实前端页面渲染生成，注明视口尺寸；不能把手绘稿、另做的静态 HTML 或 AI 绘图冒充现有界面截图。
- 交互预览优先直接运行当前项目的前端代码，并嵌入或整合到工作台。尽量不要复制出另一份难以同步的产品页面代码。
- 如果项目依赖登录、网络服务、数据库、AI、摄像头、支付或其他真实环境，给演示模式提供隔离的示例数据和可预测的模拟响应。演示操作不能改写真实用户数据、触发真实消费或调用会产生外部副作用的服务。
- 模拟内容和行为要标注为演示数据/模拟结果；能复用现有页面和交互的部分仍要复用，不要因为 mock 后端而重做一套不同的 UI。
- 覆盖主要页面与最重要的交互路径。优先做能帮助设计讨论的状态，不要为了数量堆砌截图。
- 为每个页面或重要状态说明：入口、主要内容、可执行操作、操作后的变化、如何返回，以及当前行为是代码事实、演示模拟还是待确认。
- 在同一工作台网页中提供截图与交互预览切换；预览中切换页面或状态时，说明内容应跟着更新。
- 合理适配桌面和项目主要目标视口；如果项目是移动端优先，按真实移动端尺寸呈现，并让桌面查看方便。

## 文档与维护

在项目内建立一个清楚、稳定的原型工作台目录，并至少维护：
- 使用说明：如何启动、停止、访问工作台，演示数据有什么限制。
- 页面说明：页面清单、入口、关键交互路径、状态及返回方式。
- 设计约定/讨论记录：已确认的决定、待确认事项和明确不在本次范围内的内容。
- 效果图：按页面和状态命名，注明视口尺寸；需要比较时保留有日期/版本标记的旧稿。

以后我说“出效果图”“改一下效果图”或“调整这个页面”时，默认在这套原型工作台和对应页面上继续修改、更新截图及说明；不要新建一个独立的效果图网页或另一个互不相关的原型。只有我明确说要新方向、独立方案或生产版改动时，才改变这个默认范围。

设计讨论中确认的内容要及时记入文档，区分“已确认”和“待确认”。不要把猜测写成已经确认的事实。做原型的修改不应擅自改变生产功能；需要改生产代码时先根据我的明确要求处理。

## 完成要求

- 在工作区内直接完成可运行的工作台、静态截图、关键交互、页面说明和启动说明。
- 遵循项目现有代码风格和目录约定，控制新增依赖；能使用已有浏览器/截图工具就不要引入另一套大型工具链。
- 启动工作台并在浏览器中检查：主要页面可打开、关键流程能走通、截图与交互预览风格一致、说明和实际状态对应、模拟操作不会污染真实数据。
- 告诉我新增/修改了哪些文件、如何启动和访问、当前已覆盖哪些页面与状态、哪些行为是模拟的、还有什么待确认。

请先检查当前项目，再按以上要求实施。不要只给我计划或代码片段。
```
